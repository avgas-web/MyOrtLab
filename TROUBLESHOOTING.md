1. **Динамический base path** - vite.config.js теперь автоматически определяет имя репозитория
2. **404.html для SPA** - добавлена поддержка маршрутизации для одностраничных приложений
3. **Обновлённый workflow** - автоматически копирует index.html в 404.html
4. **Относительные пути** - используются относительные пути для совместимости

## 🚀 Пошаговая инструкция по деплою

### Шаг 1: Проверьте имя репозитория

⚠️ **ВАЖНО**: Имя репозитория должно быть **точно таким**, как вы хотите видеть в URL.

Например:
- Репозиторий: `MyOrtLab`
- URL сайта: `https://ВАШ_ЛОГИН.github.io/MyOrtLab/`

### Шаг 2: Убедитесь, что все файлы загружены

В репозитории должны быть:
```
.github/workflows/deploy.yml
public/404.html
public/.nojekyll
src/
  App.tsx
  data.ts
  i18n.ts
  index.css
  main.tsx
index.html
package.json
vite.config.js
```

### Шаг 3: Проверьте настройки GitHub Pages

1. Перейдите в **Settings** → **Pages**
2. В разделе **Build and deployment**:
   - **Source**: выберите **"GitHub Actions"** (НЕ "Deploy from a branch")
3. Сохраните настройки

### Шаг 4: Проверьте workflow

1. Перейдите на вкладку **Actions**
2. Найдите workflow "Deploy to GitHub Pages"
3. Проверьте статус:
   - ✅ Зеленая галочка - успешно
   - ❌ Красный крест - ошибка (кликните для просмотра логов)

### Шаг 5: Дождитесь завершения деплоя

Обычно деплой занимает 2-3 минуты. После этого сайт будет доступен.

## 🔍 Проверка работоспособности

### Проверка 1: Откройте консоль браузера

1. Откройте сайт в браузере
2. Нажмите **F12** (или Ctrl+Shift+I)
3. Перейдите на вкладку **Console**
4. Проверьте ошибки:
   - ❌ "Failed to load resource: 404" - проблема с путями
   - ❌ "Uncaught SyntaxError" - проблема с JavaScript
   - ❌ "CORS policy" - проблема с загрузкой ресурсов

### Проверка 2: Проверьте вкладку Network

1. Откройте вкладку **Network** в DevTools
2. Обновите страницу (F5)
3. Проверьте статусы загрузки:
   - ✅ 200 OK - всё загружается
   - ❌ 404 Not Found - файл не найден
   - ❌ 403 Forbidden - доступ запрещен

### Проверка 3: Проверьте HTML

1. В вкладке **Elements** найдите `<script>` и `<link>` теги
2. Проверьте пути:
   - ✅ Должны быть относительные пути: `./assets/...`
   - ❌ Не должны быть абсолютные: `/MyOrtLab/assets/...` (если имя репозитория другое)

## 🐛 Частые проблемы и решения

### Проблема 1: Белый экран

**Симптомы**: Страница загружается, но ничего не отображается

**Решение**:
1. Откройте консоль (F12)
2. Проверьте ошибки JavaScript
3. Убедитесь, что все файлы загружаются (вкладка Network)
4. Проверьте, что в Settings → Pages выбрано "GitHub Actions"

### Проблема 2: Ошибка 404

**Симптомы**: "Page not found" или "404"

**Решение**:
1. Проверьте URL - должен быть `https://ВАШ_ЛОГИН.github.io/ИМЯ_РЕПО/`
2. Убедитесь, что имя репозитория совпадает с URL
3. Проверьте, что workflow завершился успешно
4. Подождите 5-10 минут (GitHub Pages кэширует)

### Проблема 3: Стили не загружаются

**Симптомы**: Страница отображается, но без стилей

**Решение**:
1. Откройте вкладку Network
2. Найдите CSS файл
3. Проверьте статус:
   - Если 404 - проблема с путями
   - Если 200, но стили не применяются - проблема с CSS
4. Проверьте, что в `dist/index.html` пути начинаются с `./`

### Проблема 4: JavaScript не работает

**Симптомы**: Страница отображается, но кнопки не работают

**Решение**:
1. Откройте консоль (F12)
2. Проверьте ошибки JavaScript
3. Убедитесь, что JS файл загружается
4. Проверьте, что нет ошибок CORS

### Проблема 5: Workflow не запускается

**Симптомы**: Вкладка Actions пуста или workflow не запускается

**Решение**:
1. Убедитесь, что файл `.github/workflows/deploy.yml` существует
2. Проверьте синтаксис YAML файла
3. Убедитесь, что вы запушили в ветку `main` или `master`
4. Проверьте, что в Settings → Actions → General → Workflow permissions выбрано "Read and write permissions"

### Проблема 6: Старая версия сайта

**Симптомы**: После обновления код не меняется

**Решение**:
1. Очистите кэш браузера (Ctrl+Shift+Delete)
2. Или откройте в режиме инкогнито
3. Или добавьте `?v=2` к URL для принудительного обновления
4. Подождите 5-10 минут (GitHub Pages кэширует)

## 🔧 Ручной деплой (если автоматический не работает)

Если автоматический деплой через GitHub Actions не работает, можно задеплоить вручную:

### Метод 1: Через ветку gh-pages

```bash
# Установите gh-pages
npm install --save-dev gh-pages

# Добавьте в package.json
"scripts": {
  "deploy": "gh-pages -d dist"
}

# Задеплойте
npm run build
npm run deploy
```

Затем в Settings → Pages:
- Source: "Deploy from a branch"
- Branch: "gh-pages" / "root"

### Метод 2: Через GitHub UI

1. Соберите проект локально: `npm run build`
2. Создайте новую ветку `gh-pages`
3. Загрузите содержимое папки `dist` в эту ветку
4. В Settings → Pages выберите ветку `gh-pages`
