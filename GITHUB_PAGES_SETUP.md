# 🚀 Инструкция по деплою на GitHub Pages

## ❌ Ошибка: "Get Pages site failed"

Эта ошибка возникает, когда GitHub Pages не включен в настройках репозитория.

## ✅ Пошаговая инструкция по исправлению

### Шаг 1: Включите GitHub Pages в настройках репозитория

1. Перейдите в ваш репозиторий на GitHub
2. Нажмите на вкладку **"Settings"** (Настройки) в правом верхнем углу
3. В левом меню найдите раздел **"Pages"**
4. В разделе **"Build and deployment"**:
   - **Source**: выберите **"GitHub Actions"** (НЕ "Deploy from a branch")
   - Это важно! Должно быть именно "GitHub Actions"
5. Нажмите **"Save"** (Сохранить)

### Шаг 2: Проверьте workflow файл

Убедитесь, что файл `.github/workflows/deploy.yml` существует и содержит правильный код.

**Обновленный workflow использует:**
- Node.js 22 (вместо устаревшего 20)
- `actions/configure-pages@v5` (вместо v4)
- Правильные permissions для Pages

### Шаг 3: Запустите workflow

После включения Pages:

1. Перейдите на вкладку **"Actions"** в вашем репозитории
2. Найдите workflow **"Deploy to GitHub Pages"**
4. Дождитесь завершения сборки (обычно 2-3 минуты)
5. Проверьте, что все шаги завершились успешно (зеленые галочки ✓)

### Шаг 4: Проверьте сайт

После успешного деплоя сайт будет доступен по адресу:

```
https://ВАШ_ЛОГИН.github.io/ИМЯ_РЕПОЗИТОРИЯ/
```

Например: `https://john123.github.io/MyOrtLab/`

## 🔧 Если проблема не решена

### Проверка 1: Убедитесь, что Pages включен

1. Settings → Pages
2. Должно быть написано: **"Your site is live at..."**
4. Source должен быть **"GitHub Actions"**

### Проверка 2: Проверьте логи workflow

1. Перейдите в Actions
2. Кликните на последний запуск workflow
4. Посмотрите, на каком шаге произошла ошибка
5. Проверьте сообщения об ошибках

### Проверка 3: Убедитесь, что репозиторий публичный

GitHub Pages работает только с публичными репозиториями (для бесплатных аккаунтов).

1. Settings → General
2. В разделе "Danger Zone" проверьте, что репозиторий Public
3. Если Private, нажмите "Change visibility" → "Public"

### Проверка 4: Проверьте permissions

В Settings → Actions → General:

1. Прокрутите до "Workflow permissions"
2. Выберите **"Read and write permissions"**
3. Нажмите "Save"

## 📋 Обновления в workflow файле

### Что было исправлено:

1. **Node.js версия**: 20 → 22
   - Node.js 20 устарел и вызывает ошибки
   - Node.js 22 - актуальная LTS версия

2. **Actions версия**: configure-pages@v4 → @v5
   - v4 устарела
   - v5 - актуальная версия

3. **Permissions**: добавлены правильные разрешения
   ```yaml
   permissions:
     contents: read
     pages: write
     id-token: write
   ```

## 🔄 Ручной запуск workflow

Если автоматический запуск не работает:

1. Перейдите в Actions
3. Нажмите **"Run workflow"**
4. Выберите branch: "main" или "master"
5. Нажмите **"Run workflow"**

## 📊 Ожидаемое время деплоя

- **Сборка проекта**: 1-2 минуты
- **Загрузка артефактов**: 30 секунд
- **Деплой на Pages**: 1-2 минуты
- **Общее время**: 3-5 минут

## 🐛 Частые проблемы

### Проблема 1: "Get Pages site failed"

**Решение**: Включите Pages в Settings → Pages → Source: "GitHub Actions"

### Проблема 2: "Node.js 20 is deprecated"

**Решение**: Обновите workflow файл (уже исправлено в новой версии)

### Проблема 3: "404 Not Found" после деплоя

**Решение**: 
- Проверьте, что имя репозитория совпадает с `base` в `vite.config.js`
- Подождите 5-10 минут (GitHub Pages кэширует)
- Очистите кэш браузера (Ctrl+Shift+Delete)

### Проблема 4: "Workflow failed"

**Решение**:
- Проверьте логи в Actions
- Убедитесь, что все зависимости установлены
- Проверьте, что проект собирается локально
