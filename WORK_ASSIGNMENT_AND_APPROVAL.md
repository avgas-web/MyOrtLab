# Назначение работ, техников и согласования с доктором

## Обзор изменений

В данной версии реализована полноценная система назначения работ и техников с возможностью указания, какие работы требуют согласования доктором.

---

## 1. Назначение работ и техников

### Что реализовано

✅ **Администратор может:**
- Назначать техников на каждую работу в заказе
- Добавлять новые работы к позициям заказа
- Удалять работы из позиций заказа
- Устанавливать сумму сделки для каждой работы
- Помечать работы как "требует согласования доктором"

✅ **Техники могут:**
- Видеть только свои назначения (работы, назначенные им)
- Отмечать выполнение работ (CAD или физическое производство)
- Добавлять комментарии к заказу

✅ **Доктор может:**
- Видеть работы, которые требуют согласования
- Согласовывать только работы, помеченные как "требует согласования"
- Возвращать работы в доработку с указанием причины

### Как это работает

#### Назначение техников

Администратор открывает заказ и переходит на вкладку "Позиции":

1. Находит нужную позицию
2. В колонке "Техник" выбирает техника из выпадающего списка
3. Техник автоматически получает уведомление о назначении

#### Добавление работ

Администратор может добавить дополнительные работы к позиции:

1. Нажимает кнопку "+ Работа" рядом с названием позиции
2. Вводит название работы
3. Указывает сумму сделки
4. Работа добавляется в список

#### Удаление работ

Администратор может удалить работу:

1. Нажимает кнопку "✕" рядом с названием работы
2. Подтверждает удаление
3. Работа удаляется из списка

#### Пометка "требует согласования доктором"

Администратор может пометить работу как требующую согласования:

1. Устанавливает флажок в колонке "Треб. согл."
2. Система автоматически добавляет запись в историю
3. Доктор увидит эту работу в списке на согласование

---

## 2. Флажок "требует согласования доктором"

### Что это

Поле `requiresDoctorApproval` в интерфейсе `WorkItem` указывает, требует ли данная работа согласования доктором.

### Как использовать

#### Для администратора

При создании или редактировании заказа:

1. Откройте заказ
2. Перейдите на вкладку "Позиции"
3. Найдите нужную работу
4. Установите флажок в колонке "Треб. согл."
5. Работа будет помечена как требующая согласования

#### Для доктора

Доктор видит только работы, которые:
- Помечены как `requiresDoctorApproval = true`
- Назначены ему (если он также является техником)

Доктор может:
- Согласовать работу (установить `docOk = true`)
- Вернуть работу в доработку с указанием причины

#### Для техников

Техники видят только свои назначения и могут:
- Отмечать выполнение работы (done или proddone)
- Добавлять комментарии

## 3. Движение заказа по конвейеру

### Обновленная логика переходов

#### CAD/CAM → Approve

После завершения CAD/CAM работ:
- Если есть работы, требующие согласования → переход в `approve`
- Доктор согласовывает работы с `requiresDoctorApproval = true`
- После согласования → переход в `production` или `closing`

#### Production → Approve (для физического производства)

После завершения физического производства:
- Если есть работы, требующие согласования → переход в `approve`
- Доктор согласовывает работы с `requiresDoctorApproval = true`
- После согласования → переход в `delivery` или `closing`

#### Production → Delivery/Closing

Если нет работ, требующих согласования:
- Переход напрямую в `delivery` (для полного маршрута)
- Или в `closing` (для маршрута только физическое производство)

### Примеры сценариев

#### Сценарий 1: CAD/CAM без согласования

```
1. Администратор создает заказ
2. Добавляет работу "CAD-моделирование"
3. НЕ помечает как "требует согласования"
4. Назначает техника
5. Техник выполняет работу (done = true)
6. Переход: cadcam → production/closing (без согласования)
```

#### Сценарий 2: CAD/CAM с согласованием

```
1. Администратор создает заказ
2. Добавляет работу "CAD-моделирование коронки"
3. Помечает как "требует согласования" ✓
4. Назначает техника
5. Техник выполняет работу (done = true)
6. Переход: cadcam → approve
7. Доктор видит работу на согласование
8. Доктор согласовывает работу (docOk = true)
9. Переход: approve → production/closing
```

#### Сценарий 3: Физическое производство с согласованием

```
1. Заказ в статусе production
2. Техник выполняет работу (proddone = true)
3. Работа помечена как "требует согласования"
4. Переход: production → approve
5. Доктор видит работу на согласование
6. Доктор согласовывает работу (docOk = true)
7. Переход: approve → delivery/closing
```

#### Сценарий 4: Смешанный заказ

```
1. Заказ содержит несколько работ:
   - Работа 1: CAD-моделирование (требует согласования)
   - Работа 2: Фрезеровка (не требует согласования)
   - Работа 3: Керамика (требует согласования)

2. Техник выполняет все работы
3. Переход: production → approve (есть работы с согласованием)
4. Доктор согласовывает только работы 1 и 3
5. Работа 2 не требует согласования
6. Переход: approve → delivery/closing
```

### Новые функции в OrderModal

#### addWorkItem(posId: string)
Добавляет новую работу к позиции заказа.

```typescript
const addWorkItem = (posId: string) => {
  const workTypeName = prompt('Введите название вида работы:');
  if (!workTypeName) return;
  
  const fee = Number(prompt('Введите сумму сделки (₽):', '0') || '0');
  
  updateData((d: AppData) => {
    const o = d.orders.find(x => x.id === order.id);
    if (!o) return d;
    const pos = o.positions.find(p => p.id === posId);
    if (!pos) return d;
    
    const newWorkItem: WorkItem = {
      id: genId(),
      wtId: '',
      name: workTypeName,
      techId: '',
      fee: fee,
      done: false,
      proddone: false,
      docOk: false,
      docOkAt: null,
      assignedAt: Date.now(),
      completedAt: null,
      mats: [],
      requiresDoctorApproval: false
    };
    
    pos.ops.push(newWorkItem);
    o.history.push({ at: Date.now(), by: user.id, txt: `Добавлена работа: ${workTypeName}` });
    return {...d};
  });
  refreshOrderLocal(order.id);
  toast('Работа добавлена');
};
```

#### removeWorkItem(posId: string, opId: string)
Удаляет работу из позиции заказа.

```typescript
const removeWorkItem = (posId: string, opId: string) => {
  if (!confirm('Удалить эту работу?')) return;
  
  updateData((d: AppData) => {
    const o = d.orders.find(x => x.id === order.id);
    if (!o) return d;
    const pos = o.positions.find(p => p.id === posId);
    if (!pos) return d;
    const op = pos.ops.find((x: WorkItem) => x.id === opId);
    if (!op) return d;
    
    pos.ops = pos.ops.filter((x: WorkItem) => x.id !== opId);
    o.history.push({ at: Date.now(), by: user.id, txt: `Удалена работа: ${op.name}` });
    return {...d};
  });
  refreshOrderLocal(order.id);
  toast('Работа удалена');
};
```

if (s === 'approve' && isDoctor && order.positions.some(p => p.ops.some((o: WorkItem) => o.requiresDoctorApproval && !o.done))) {

## 6. Преимущества

### Для администратора

✅ **Гибкость** - можно добавлять/удалять работы динамически  
✅ **Контроль** - можно назначать любых техников на любые работы  
✅ **Управление согласованиями** - можно указывать, какие работы требуют согласования  
✅ **Прозрачность** - вся история изменений записывается  

### Для техников

✅ **Фокус** - видят только свои назначения  
✅ **Ясность** - четко понимают, какие работы нужно выполнить  
✅ **Эффективность** - не отвлекаются на чужие задачи  

### Для доктора

✅ **Релевантность** - видит только работы, которые действительно нужно согласовать  
✅ **Экономия времени** - не тратит время на просмотр всех работ  
✅ **Контроль качества** - может возвращать работы в доработку
