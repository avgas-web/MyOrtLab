# Инструкция по деплою на GitHub Pages

## ✅ Что уже настроено

В проекте уже созданы все необходимые файлы для автоматического деплоя:

1. **vite.config.js** - настроен `base: '/MyOrtLab/'` для корректной работы путей
2. **.github/workflows/deploy.yml** - GitHub Actions workflow для автоматического деплоя
3. **public/.nojekyll** - файл для отключения Jekyll на GitHub Pages

## 🚀 Пошаговая инструкция по деплою

### Шаг 1: Создание репозитория на GitHub

1. Перейдите на [github.com](https://github.com)
2. Нажмите **"New repository"** (Новый репозиторий)
3. Заполните поля:
   - **Repository name**: `MyOrtLab` (важно: имя должно совпадать с `base` в vite.config.js)
   - **Description**: "Система управления зуботехнической лабораторией"
   - **Public** (публичный) - обязательно для бесплатного GitHub Pages
   - **Initialize this repository with**: НЕ выбирайте README, .gitignore или license
4. Нажмите **"Create repository"**

### Шаг 2: Загрузка кода в репозиторий

#### Вариант A: Через GitHub UI (простой)

1. В созданном репозитории нажмите **"uploading an existing file"**
2. Перетащите ВСЕ файлы проекта в окно загрузки
3. Внизу страницы нажмите **"Commit changes"**

#### Вариант B: Через Git (рекомендуемый)

```bash
# В папке с проектом
git init
git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/MyOrtLab.git
git push -u origin main
```

### Шаг 3: Настройка GitHub Pages

1. Перейдите в репозиторий на GitHub
2. Нажмите **"Settings"** (Настройки) в правом верхнем углу
3. В левом меню выберите **"Pages"**
4. В разделе **"Build and deployment"**:
   - **Source**: выберите **"GitHub Actions"**
5. GitHub автоматически запустит workflow из файла `.github/workflows/deploy.yml`

### Шаг 4: Ожидание деплоя

1. Перейдите на вкладку **"Actions"** в вашем репозитории
2. Вы увидите запущенный workflow "Deploy to GitHub Pages"
3. Дождитесь завершения (обычно 2-3 минуты)
4. Когда workflow завершится успешно, появится зеленая галочка ✓

### Шаг 5: Проверка сайта

Ваш сайт будет доступен по адресу:
```
https://ВАШ_ЛОГИН.github.io/MyOrtLab/
```

Например: `https://john123.github.io/MyOrtLab/`

## 🔧 Решение проблем

### Проблема 1: Сайт не открывается (404)

**Причина**: Неправильное имя репозитория

**Решение**: 
- Имя репозитория должно точно совпадать с `base` в `vite.config.js`
- Если репозиторий называется `MyOrtLab`, то в vite.config.js должно быть `base: '/MyOrtLab/'`
- Если репозиторий называется по-другому, измените `base` в vite.config.js

### Проблема 2: Белый экран или ошибки загрузки

**Причина**: Неправильные пути к ассетам

**Решение**:
1. Убедитесь, что в `vite.config.js` есть `base: '/MyOrtLab/'`
2. Пересоберите проект: `npm run build`
3. Проверьте, что в папке `dist/index.html` пути начинаются с `/MyOrtLab/`

### Проблема 3: Workflow не запускается

**Причина**: Не включены GitHub Pages

**Решение**:
1. Перейдите в Settings → Pages
2. В разделе "Source" выберите "GitHub Actions"
3. Сохраните изменения

### Проблема 4: Ошибка "Page build failed"

**Причина**: Ошибка в коде или конфигурации

**Решение**:
1. Перейдите на вкладку "Actions"
2. Найдите失败的 workflow
3. Посмотрите логи ошибок
4. Исправьте ошибки и сделайте новый commit

### Проблема 5: Сайт открывается, но стили не загружаются

**Причина**: Неправильный base path

**Решение**:
1. Проверьте `vite.config.js` - должен быть `base: '/MyOrtLab/'`
2. Убедитесь, что имя репозитория совпадает с base path
3. Пересоберите и запушьте изменения

## 📝 Альтернативный вариант: Деплой через ветку gh-pages

Если автоматический деплой через GitHub Actions не работает, можно использовать старый метод:

### Шаг 1: Установка gh-pages

```bash
npm install --save-dev gh-pages
```

### Шаг 2: Добавление скрипта в package.json

Добавьте в `package.json`:
```json
{
  "scripts": {
    "deploy": "gh-pages -d dist"
  }
}
```

### Шаг 3: Деплой

```bash
npm run build
npm run deploy
```

### Шаг 4: Настройка GitHub Pages

1. Settings → Pages
2. Source: "Deploy from a branch"
3. Branch: "gh-pages" / "root"
4. Save

## 🔄 Автоматический деплой при каждом push

Workflow уже настроен на автоматический деплой при каждом push в ветку `main` или `master`.

Это означает:
- Каждый раз, когда вы делаете `git push`, сайт автоматически пересоберется и задеплоится
- Не нужно вручную запускать деплой
- Можно отслеживать статус деплоя на вкладке "Actions"

## 📊 Проверка статуса деплоя

1. Перейдите в репозиторий
2. Нажмите на вкладку **"Actions"**
3. Вы увидите список всех запусков workflow
4. Зеленая галочка ✓ - успешно
5. Красный крест ✗ - ошибка (кликните для просмотра логов)

## 🔐 Безопасность

- GitHub Pages хостится на HTTPS по умолчанию
- Все данные хранятся в localStorage браузера пользователя
- Нет серверной части - все работает на клиенте

## 💡 Советы

1. **Используйте кастомный домен** (опционально):
   - Можно привязать свой домен к GitHub Pages
   - Инструкция: Settings → Pages → Custom domain

2. **Кэширование**:
   - GitHub Pages кэширует файлы
   - После обновлений может потребоваться Ctrl+F5 для очистки кэша

3. **Лимиты GitHub Pages**:
   - Размер репозитория: до 1 GB
   - Размер сайта: до 1 GB
   - Трафик: до 100 GB/месяц
   - Для нашего проекта это более чем достаточно

4. **SEO**:
   - GitHub Pages индексируется поисковыми системами
   - Можно добавить мета-теги для улучшения SEO
