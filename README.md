# 🦷 MyOrtLab/GnatOne - Личный кабинет зуботехнической лаборатории

[![React](https://img.shields.io/badge/React-18.3.1-blue)](https://reactjs.org/)
[![TypeScript](https://img.shields.io/badge/TypeScript-5.6.2-blue)](https://www.typescriptlang.org/)
[![Vite](https://img.shields.io/badge/Vite-6.0.3-purple)](https://vitejs.dev/)
[![Tailwind CSS](https://img.shields.io/badge/Tailwind-3.4.17-blue)](https://tailwindcss.com/)

Полнофункциональное веб-приложение для управления зуботехнической лабораторией с поддержкой многопользовательской работы, конвейерной обработки заказов и CRM-функций.

---

## ✨ Возможности

### 📋 Управление заказами
- **Основной конвейер**: Полный цикл от проверки файлов до сдачи
- **Ремонтные работы**: Отдельная ветка с согласованием
- **Гарантийные работы**: Бесплатный ремонт по заявке
- **Автоматическое определение маршрута**: Полный / Только CAD/CAM / Только физика
- **Канбан-доска**: Визуализация всех статусов

### 👥 Пользователи и роли
- 14 типов ролей с разграничением прав
- Индивидуальные права доступа для каждого пользователя
- Управление подписками GMAI

### 🏥 Пациенты
- Создание и управление пациентами
- Привязка к докторам
- История заказов

### 📦 Материалы
- Учёт остатков
- Приход и расход
- Автоматическое списание при выполнении работ
- Отчёты по расходу

### 🤖 GnatoneMirror (AI)
- Генерация AI-отчётов для пациентов
- Планы лечения
- Рекомендации по конструкциям

### 📊 Аналитика и отчёты
- KPI дашборды
- Отчёты по техникам
- Прибыльность заказов
- Экспорт в CSV

### 🔔 Уведомления
- Telegram
- Max
- Email

### 🌍 Мультиязычность
- Русский
- English
- Қазақша

## 🚀 Быстрый старт

### Установка

```bash
# Клонирование репозитория
git clone <repository-url>
cd myortlab

# Установка зависимостей
npm install

# Запуск в режиме разработки
npm run dev
```

Приложение будет доступно по адресу: `http://localhost:5173`

### Сборка для продакшена

```bash
npm run build
```

Собранные файлы будут в директории `dist/`

## 📊 Статусы заказов

### Основной конвейер
```
quality → accept → gypsum → scanning → admin_pricing → payment → 
cadcam → approve → production → delivery → handover → closing → done
```

### Ремонт
```
repair_create → repair_approve → payment → production → delivery → closing → done
```

### Гарантия
```
guarantee_create → guarantee_approve → production → delivery → done
```

## 🎯 Основные функции

### Создание заказа
1. Выбор типа (обычный / ремонт / гарантия)
2. Выбор пациента (или создание нового)
3. Добавление услуг из каталога
4. Автоматическое определение маршрута
5. Загрузка файлов
6. Установка срока сдачи

### Управление заказами
- Просмотр всех заказов в канбан-доске
- Фильтрация по статусу и категории
- Поиск по номеру, пациенту, услуге
- Переходы между статусами
- Назначение техников
- Согласование работ
- Коррекции с указанием причины

### Управление материалами
- Номенклатура материалов
- Приход материалов
- Автоматическое списание
- Отчёты по расходу
- Предупреждения о минимальном остатке

### Отчёты
- По технику
- Сделка техников
- Прибыльность внутренних заказов
- Экспорт в CSV

## 🔧 Конфигурация

### Настройка уведомлений

В разделе "Уведомления" администратор может настроить:

**Telegram:**
- Bot Token
- Chat ID

**Max:**
- API Key
- Chat ID

**Email:**
- SMTP хост
- SMTP порт
- SMTP пользователь
- SMTP пароль
- Email отправителя

В настройках можно указать URL сайта элайнеров, который будет открываться при клике на пункт меню "Элайнеры".

## 🎨 Особенности интерфейса

- **Компактный дизайн** - вся информация на одном экране
- **Канбан-доска** - визуализация всех статусов с отдельной полосой прокрутки

## 🔒 Безопасность

⚠️ **Важно**: В демо-версии данные хранятся в localStorage. Для продакшена необходимо:
- Использовать базу данных
- Реализовать JWT авторизацию
- Хешировать пароли
- Использовать HTTPS

---

## 🚧 Известные ограничения

- Данные хранятся в localStorage (демо-режим)
- Нет реальной интеграции с AI-сервисом (webhook заглушка)
- Уведомления не отправляются (только настройка)
- Нет бэкенда (все данные на клиенте)
